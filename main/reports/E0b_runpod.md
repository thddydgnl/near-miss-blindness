**고정물 위치(E0b 발견, 프로토콜에 반영).** LIBERO의 고정물(캐비닛, 스토브, 와인 랙)은 `env.reset()`마다 ±1cm 안에서 무작위로 다시 놓인다. 이 위치는 평평한 MuJoCo 상태에 들어 있지 않다(`dbg_fixtures.py`).
- 그대로 두면 같은 반사실도 프로세스가 그전에 무엇을 돌렸는지에 따라 결과가 바뀐다. 예: t2 d18 명목 재생이 새 환경에서는 실패, 다른 rollout 뒤에는 성공.
- 물리와 다른 환경에서 렌더링하면 프레임이 물리와 최대 약 1–1.5cm 어긋난다.
- 고침
  - 모든 reset 전에 환경을 먼저 만든 뒤, (task, demo)(E1) 또는 job id(E2)에서 나온 안정 seed로 `np.random`·`env.seed`를 고정한다.
  - 렌더 환경의 `body_pos`/`body_quat`는 물리 환경에서 복사한다(`b_cf.py`, `b_runner.py`).
  - 새 환경과 재사용 환경에서 결과가 같고 렌더 동기화가 맞는 것을 확인했다(`dbg_determinism2.py`).
- E0b 첫 데이터(v1)로 낸 판정기·보정 수치는 폐기하고, 고친 데이터(v2)로 다시 냈다.
- 같은 무작위성은 CureWM 프로토콜에도 있다. 재생 필터와 결과가 reset마다 달라질 수 있다. E0의 CureWM 재현은 그들의 백엔드를 그대로 써서, 프레임과 물리는 일치한다.

### 3.2 (c) value head

- 승인된 규칙대로 끝 정렬 질의만 쓴다. runner가 반사실마다 다음을 기록한다.
  - V(k청크 끝, 들어 올리기 전)
  - V(들어 올리기 뒤)
  - 청크별 V
  - 실제 최종 상태의 V(마지막 실제 청크의 시작 관측 + 실제 끝 상태)

## 5. 질의 프로토콜(DESIGN_main 입력)

- **r**
  - 마지막 행동 뒤 정착 15 step(무동작, 그리퍼 열림)의 상태에서 r = e/τ(E0 정의)를 잰다. 성공은 r < 1 ∧ aux(= LIBERO 술어)다.
  - 들어 올리기가 LIBERO 결과를 바꾼 비율은 반사실 v2 전체에서 0.1–1.5%(과제별 1–15건)이고 기록한다.
  - "한 번이라도 성공"(LIBERO 종료 규칙)과 정착 상태의 불일치도 기록한다(t5 6%, t2 3% 등).
- **들어 올리기 청크(LIFT)**: 3 step 그리퍼 열기 + 13 step +z(행동 1.0). 실제와 상상 모두 끝에 붙인다. 판정기 (a)·(d)는 이 뒤의 프레임을 판정한다.
- **E1(끝 정렬)**
  - k = 1..4마다 실제 상태 S_{T−16k}(행동 T−16k 직전)의 렌더 관측(모델 시야)에서 시작한다.
  - 실제 행동 k청크와 LIFT를 상상한다(질의 k+1회, 행동 패스 1단계. E0에서 출력이 5단계와 같음을 확인).
  - (c)는 k번째 청크 끝의 V다. (a)·(d)는 들어 올리기 뒤 상상 프레임과 실제 프레임이다.
  - 실제 최종 상태 V를 같이 낸다. 모든 판정 프레임의 DINOv2 특징을 저장한다(H1b AUROC용).
- **E2**
  - 실제 episode: 시드 고정 reset, 무동작 10 step, DP 16-step 청크를 끝까지 실행(성공은 아무 step에서나 LIBERO 성공), 최대 300 step
  - 끝 상태는 청크 경계다. 정착 → r을 재고, LIFT → 실제 판정 프레임을 얻는다.
  - **모드 O**: 첫 관측(무동작 뒤)에서 실행된 청크 전체 + LIFT를 상상한다.
  - **모드 C**(DP만): 첫 관측에서 정책이 상상 관측을 보고 H_C청크를 행동한 뒤 LIFT를 붙인다.
    - H_C = ceil(1.25 × 데모 길이 p90 / 16): t1 9, t2 11, t4 9, t5 16, t6 11, t8 9
  - 판정기는 E1과 같다. 실제 끝 상태 V도 낸다.
- 모든 질의는 seed 195로 고정. GPU 비결정성 때문에 같은 질의를 다시 돌리면 value가 최대 약 0.001 다르다.

## 6. LIBERO Diffusion Policy

- **데이터**(`dp_data.py`)
  - 과제당 공식 데모 50개를 기록된 MuJoCo 상태에서 256px로 다시 렌더링했다(재생 오차 없음).
  - Cosmos 모델 시야(상하 반전 → JPEG95 → 224 → 90% 중앙 crop → 224)로 바꾼 뒤 128px로 줄였다.
  - 3인칭 + 손목, proprio 9차원(Cosmos 순서)
  - 과제당 4,669–7,638 step, 약 60초
- **모델·학습**(`dp_model.py`, `dp_train.py`)
  - CNN Diffusion Policy: ResNet-18-GN × 2 + UNet1D(256, 512, 1024), 100M
  - 행동 16 step을 open-loop로 모두 실행(Cosmos 청크와 같음), n_obs_steps 1
  - DDPM 100 / DDIM 10, 배치 64, AdamW 1e-4, cosine, EMA, ±6px 이동 증강

## 7. 다중 pod runner

- 파일
  - `b_runner.py`(실행), `make_manifest.py`(매니페스트), `merge_runs.py`(맥북 병합), `b_cf.py`(반사실), `b_judges.py`(판정기), `cp_common.py`(Cosmos 질의)

  - `cf`: 반사실 생성(CPU)
  - `imagine`: E1 끝 정렬 상상과 판정(GPU)
  - `policy_ep`: E2 실제 episode(CPU + 작은 GPU)
  - `imagine_ep`: E2 모드 O·C(GPU)
- **결과**
  - `<root>/<stage>/results/<kind>/<job_id>.json`을 원자적으로 쓴다(이 파일이 완료 표시).
  - 판정 프레임의 DINOv2 특징은 `small/<job_id>.npz`(작음, 결과와 함께 회수)에 둔다.
  - 렌더·상태·행동은 `art/<job_id>.npz`(pod 안에서만 쓰고 회수하지 않음)에 둔다.
- **재시작과 새 pod**
  - 결과 파일이 있거나 `--done` 목록(맥북에서 병합해 넘김)에 있는 job은 건너뛴다.
  - imagine job의 cf 산출물이 없으면(이전 pod에서 만든 경우) cf를 먼저 다시 만든다.
  - cf와 policy_ep는 seed 고정이라 결정적이다.
- **병렬 pod**: `--shard i/N`(job id의 crc32 mod N). pod마다 결과를 받아 `merge_runs.py`로 합치고, 충돌(같은 job의 다른 결과)을 검사한다.
- **스모크 시험**(모두 E0b 시작 상태)
  - E1 경로(held 반사실 4개): 8/8 job, 오류 0, imagine job 하나에 약 13초
  - 판정기 내장 상태(CNN (a) + 7B (d)): 8/8, 오류 0
  - E2 경로(t8 DP 5k checkpoint, held 시작 상태 2개, 모드 O + 모드 C): 4/4, 오류 0. 두 episode 모두 성공
  - 중단 시험: 첫 imagine 결과 직후 runner를 죽이고 다시 실행하자, 남은 job만 돌고 8/8 완료
  - 새 pod 시험: 결과 파일 없이 done 목록만 넘기자 필요한 cf 2개를 다시 만들었다. cf 기록이 원래와 같았고, imagine 2개만 다시 돌았다(value 차이 최대 0.001)
  - 대규모 cf 시험: frozen severity 검증 1,056 job, 오류 0, 2.4 cf/s(7 workers 환산)
- **E1 실행 권장 순서**
  1. pod 1: 후보 11,280 cf(약 1.3시간)
  2. 맥북에서 병합 → `e1-select`로 선택 매니페스트(cf + imagine 4,200쌍)
  3. pod 2–4: shard 3개로 imagine. pod마다 자기 shard의 cf 산출물을 결정적으로 다시 만든다(CPU, GPU 작업과 겹침)
- **E2 전에 추가할 것**: π0.5와 OpenVLA-OFT용 policy 어댑터(지금 runner는 DP만 지원)
- **E1 첫 pod가 할 일**: 판정기 (a) 가중치를 다시 만든다(10절 1번). 지금 가중치는 pod와 함께 사라졌다.

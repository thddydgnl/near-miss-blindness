## 3. PushT 실패 거리 r = e/τ: 두 정의와 성분 기록

- 구현: `r12lib.margin_parts`(평가기 `PushTWrapper.eval_state`와 같은 식), DP episode용 `dp_rollout.final_parts`
  - **원 정의(agent 포함)**: r = max(‖Δ(agent xy, block xy)‖₂ / 20 px, |Δθ| / (π/9)). |Δθ|는 2π 접기. r < 1 ⟺ `eval_state` 성공.
  - **물체 자세만**: r_obj = max(‖Δblock xy‖₂ / 20 px, |Δθ| / (π/9)). agent 위치는 무시한다.
  - 기록 성분(궤적마다): agent 거리, block 거리, 각도 차, r_pos, r_ang, r_obj_pos, 두 정의의 구간(bin, bin_obj)과 성공 여부. near-miss 구성은 지배 항(agent 위치 / block 위치 / 각도)으로 나눈다(R2-12 D4와 같은 규칙).
- R2-12 집합을 두 정의로 다시 나눈 결과(`m1/robj_e0.json`, main 정책 8개 3,200 궤적)
  - 원 정의 near 731개 가운데 604개는 r_obj로는 성공이다. 구성은 agent 위치 621, block 위치 95, 각도 15다(R2-12 D4와 같음).
  - r_obj near는 276개뿐이다(원 near에서 127, mid에서 51, far에서 98). 교란 정책들의 near-miss 대비는 거의 agent 위치의 대비다. 설계 7장의 위험("near-miss의 85%가 agent 위치 오차")이 그대로 확인된다.
- r_obj 라벨 판별기의 가능성(`m1/judges_obj_e0.json`, 같은 학습 집합에 라벨만 r_obj < 1)
  - (a_obj) held-out 정확도 **0.962**(기준 0.95 통과). (b_obj) τ = 0.345, held-out 0.894
  - main 집합(r_obj near 276개, 기술 통계): 성공 대 near AUROC 실제 0.989 → 상상 H5 0.922, H10 0.809. 성공 대 far는 1.000 → 0.994(H5), 0.950(H10)
  - 원 정의와 같은 모양(near-miss에서만 크게 떨어지고 horizon과 함께 커짐)이 물체 자세 정의에서도 보인다. 다만 near 표본이 작아 E1의 반사실 grid로 늘려야 한다(8.5절).

### 4.2 해결책

- 두 환경의 차이
  - DP 환경의 행동은 PD 목표의 절대 위치 A(512 px 좌표)다.
  - DINO-WM 환경(`PushTWrapper`, relative=True, action_scale=100)은 env 단위 상대 행동 a를 받아 PD 목표를 agent_t + 100a로 둔다(agent_t는 그 제어 step 시작 시점 위치).
  - 그 밖의 물리(PD 계수, 100 Hz / 10 Hz, 벽, agent 원, T 기하와 질량)는 코드가 같다. DINO-WM 쪽에만 있는 것은 agent 속도 관측과 상태 설정, 렌더 크기 224(DP 96), 모양 선택지, 성공 시 종료 없음(done=False)이다.
- **변환: a_t = (A_t − agent_t) / 100**(env 단위). DINO-WM 환경의 PD 목표가 정확히 A_t가 되므로 DP 환경과 같은 궤적이 나온다(C3에서 차이 0).
  - 이것은 DINO-WM 학습 데이터 자체의 규약이다(C4). DINO-WM의 행동 정규화 통계도 바로 이 표준 시연에서 계산된 것이다(C6). 변환된 DP 행동은 형식과 분포 모두 DINO-WM 학습 분포 안에 있다.
- 관측: DP 저차원 정책의 관측(block keypoint 9개 + agent xy)은 DINO-WM 환경 상태에서 DP 자체 keypoint 생성기로 계산한다(C2).
- 프로토콜(DP 표준, `dp_rollout.py`)
  - 초기 상태: DP 공식 그대로(RandomState(seed)로 agent xy, block xy, 각도). DINO-WM 환경의 `_set_state` 순서(legacy=False)를 쓴다. 시연과 일치하는 쪽이다(C3).
  - n_obs 2(처음 관측 반복으로 채움), n_action 8, DDPM 100 step
  - coverage > 0.95면 성공으로 종료(DP 환경과 같음, DINO-WM 환경에는 종료가 없어 runner가 판단), 300 step에서 시간 초과
- 모드 O(상상 재생, `dp_imagine.py`)
  - 기록한 a_t를 그대로 재생한다.
  - 창은 episode의 마지막 5H 제어 step, 시작 관측은 그 시점의 실제 1프레임 + proprio(R2-12와 같은 DINO-WM 계획 규약)
  - 실제 창 시작·끝 프레임은 초기 상태에서 기록 행동을 정확히 재생해 그린다(재생 오차 ≤ 8e-11 px).
- **설계를 바꿀 필요가 없다.** 정책은 표준 시연으로 학습하고, DINO-WM이 학습한 환경에서 그대로 실행하며, 실행한 행동열이 정확히 같은 규약으로 상상에 들어간다.

| E5 | M1 데이터 쪽 5종(미세조정 + 재평가 각 약 40분), M3 5종 × 3 seed, 평가 쪽 MC dropout(K = 16, 상상 약 15만) | 약 4~5 | 6 |
| E6 | E2 재사용, 선택 사항인 소형 RL 루프 | 약 1~2 | 3 |
| 합계 | | **약 12~18 GPU-시간**(벽시계 25~50시간) | 48 |

- 서버 예산(48 GPU-시간) 안이다. 큰 불확실성은 셋이다.
  - (i) E3 VLM 처리량은 측정하지 않았다.
  - (ii) DINO-WM 미세조정 step 수는 E4a 사전등록에서 정해야 한다. 2만 step이면 조건당 약 2시간이다.
  - (iii) M3 해상도 sweep의 디스크: 토큰 256 × PCA 384로 3만 episode bank를 만들면 seed당 약 38GB라 실행할 수 없다. PCA 64나 episode 수를 줄인 설정이 필요하다.
- E0 자체 사용: GPU 1 약 2.4시간(13:24~15:46Z, 여러 작업이 함께 씀). 설계 E0 서버 몫 7 GPU-시간 안이다.

## 8. DESIGN_main 고정을 위한 M1·M3 입력 (초안)

가설, 지표, 판정 문턱은 설계 문서 그대로다. 아래는 설계가 "사전등록한다"고 비워 둔 세부를 E0 결과로 채운 초안이다. 결정이 필요한 항목은 9장에 따로 모았다.

### 8.1 실패 거리 e/τ

| 모델·집합 | 정의 | 목표 | 비고 |
|---|---|---|---|
| M1 dset 목표 집합(E1 반사실, R2-12 교란 정책) | 원 정의 r = max(‖Δ(agent, block) xy‖₂ / 20 px, \|Δθ\| / (π/9)) | 전문가 구간의 결과 상태(DINO-WM `goal_source=dset`, goal_H = H) | `eval_state`와 같음 |
| 같은 집합 | 물체 자세만 r_obj = max(‖Δblock xy‖₂ / 20 px, \|Δθ\| / (π/9)) | 같음 | 20 px와 π/9는 평가기 문턱을 물체 항에만 적용한 것 |
| M1 DP episode(표준 PushT 과제) | r_obj만 정의된다 | 고정 목표 자세 (256, 256, π/4) | 표준 과제에는 agent 목표가 없어 원 정의를 쓸 수 없다(9장 결정 1). coverage(최종·최대)와 DP 고유 성공(coverage > 0.95 도달)은 보조로 기록 |
| M3 | r = \|e\| / w(정렬 오차 / 물체 반폭) | 결정론적 장면 | R2-9 그대로 |

- 궤적마다 성분을 기록한다: agent 거리, block 거리, 각도 차, r_pos, r_ang, r_obj_pos. near-miss는 지배 항(agent 위치 / block 위치 / 각도)으로 나눠 보고한다.
- 곡선 분석은 달성된 r로 한다(표적 r*가 아니라).

### 8.2 구간 경계

- 모든 정의에 같은 경계를 쓴다: 성공 r < 1, near 1 ≤ r < 2, mid 2 ≤ r < 3, far r ≥ 3(왼쪽 닫힘). 주 분석은 연속 곡선이다.
- M3 보조 구간 [1, 1.2)를 함께 보고한다.
- M3 주의(9장 결정 3)
  - R2-9의 π5 far-failer는 r ∈ [1.5, 2.0)에서 실패하므로 설계 구간으로는 near다. 설계 구간으로 n_π를 재면 π5와 π6이 둘 다 50%가 되어 대조가 사라진다. R2-9 보조 구간 [1, 1.2)로는 47% 대 0%다.
  - M3 학습 데이터의 실패는 r ~ U[1, 2)뿐이다. r ≥ 2 곡선은 학습 분포 밖 외삽이다.

### 8.3 판정기 학습과 문턱

- (a) oracle 판별기
  - R2-12 구조(PairJudge: [z, z_g, z − z_g] 토큰 → 2층 d = 128 → CLS, 클래스 균형 BCE + 보조 log r 회귀)와 선택 규칙(held-out 균형 정확도 최고 epoch)을 그대로 쓴다.
  - 정의마다 따로 학습한다: a_full(r < 1), a_obj(r_obj < 1), a_std(DP 표준 목표, r_obj < 1).
  - **K = 5 seed 앙상블(확률 평균 ≥ 0.5)을 제안한다.** E0에서 단일 판별기의 0.5 문턱 운영점과 정책 수준 순위 지표가 학습 실현값에 크게 흔들렸다(2.2절: P(성공 \| near) 상상 0.18~0.26, 정책 Spearman 0.24~0.69). AUROC는 안정했다(±0.003). 앙상블 구성원 사이 표준편차를 함께 보고한다.
  - 사용 조건은 설계대로 실제 프레임 held-out 정확도 ≥ 0.95다. E0 값: a_full 0.953~0.958, a_obj 0.962, a_std 0.975
- (b) 목표 latent 거리 문턱
  - d_vis = 패치·채널 평균 제곱 거리. τ는 판별기 학습 집합의 학습 부분 실제 프레임에서 균형 정확도를 최대로 하는 값이다.
  - E0 값: τ_full = 0.2125(R2-12와 같음), τ_obj = 0.345
  - DP 표준 목표에는 정의하지 않는다. 목표 프레임의 agent 위치가 임의라서 d_vis가 agent 위치 차이에 지배된다(9장 결정 1).
- (d) VLM(E3)
  - DINO-WM 상상은 latent다. VLM에 보이려면 디코딩이 필요하다. 체크포인트에 VQ-VAE decoder(10.1M 파라미터)가 들어 있다.
  - 실제 프레임도 encode → decode를 거쳐, decoder의 흐림이 실제와 상상 양쪽에 똑같이 들어가게 한다.
- 공통
  - 지각 바닥(실제 프레임 near 오판)을 먼저 보고한다.
  - 모든 문턱과 판별기는 평가 집합을 상상하기 전에 고정한다.

### 8.5 반사실 severity grid 보정 계획 (r ∈ [0.8, 3])

- M1(`cf_grid_pilot.py`, 시뮬레이터만, E0에서 실현 가능성 확인)
  - 반사실 하나 = 성공한 전문가 구간 + severity s × 고정 교란 패턴
    - 패턴 offset: 무작위 단위 벡터, 구간 내내 일정
    - 패턴 iid: step마다 N(0, I)
    - 두 패턴을 반씩 쓴다.
  - 표적 r*마다 s를 이분 탐색(14회, s 상한 offset 40 px, iid 60 px)으로 정해 달성 r이 r*에 오게 한다. 패턴은 고정하고 크기만 바꾼다.
  - E0 결과(val, H5·H10, 각 400 episode, seed 4045·4050). 실현 가능성 점검용이다. E1의 보정 sweep은 8.7절대로 train 분할에서 한다.

| 정의 / 패턴 | 도달 가능 비율 H5 / H10 | \|r − r*\| 중앙값 | \|r − r*\| < 0.1 비율 | 달성 near의 지배 성분 |
|---|---|---|---|---|
| r / offset | 1.00 / 1.00 | 0.0003 / 0.0008 | 1.00 / 0.95 | agent 92% / 74% |
| r / iid | 0.97 / 1.00 | 0.0001 / 0.0003 | 0.99 / 0.93 | agent 79% / 54% |
| r_obj / offset | **0.50** / 0.85 | 0.0002 / 0.0006 | 0.99 / 0.91 | block 75% / 82% |
| r_obj / iid | **0.54** / 0.83 | 0.0002 / 0.0004 | 0.94 / 0.89 | block 82% / 79% |

  - 제안
    - horizon H ∈ {3, 5, 7, 10}과 정의 d ∈ {r, r_obj}마다 r*를 [0.8, 3]에 층화 균등으로 3,000개 둔다. 기울기 추정용 꼬리로 [0.2, 0.8)에 300개, [3, 6]에 300개를 더한다.
    - 도달하지 못한 표적은 새 episode에서 다시 뽑고, 도달 비율을 보고한다.
    - 모든 궤적에 두 정의의 달성 r을 기록한다. 곡선 분석은 두 grid의 궤적을 모두 써서 정의별로 한다.
    - 결과: H·정의마다 near-miss 약 1,350개(설계 기준 1,000개 이상), 궤적 3,600개(기준 3,000개 이상). 모두 시뮬레이터만으로 정하므로 상상 전에 고정된다.
- M3
  - r을 직접 지정할 수 있다. r ∈ {0.60, 0.65, …, 3.00}(49점) × 장면 128개 = 모델당 6,272 궤적, near 구간 2,560개
  - r·w가 화면 범위(±0.45)를 넘지 않게 r ≥ 3에서는 w ≤ 0.13 장면만 쓰는 것을 제안한다.

  - 평가: val 분할(21개, 월드모델 미학습). 보조로 train 분할 중 판별기 궤적을 뺀 것(월드모델 학습 데이터, R2-12 trainsplit)

### 8.8 DP 모드 O 프로토콜

- 실제 실행
  - DINO-WM 환경, DP 표준 초기 상태, coverage > 0.95면 종료, 300 step에서 시간 초과
  - 참값은 최종 상태의 r_obj다.
- 상상
  - 마지막 5H 제어 step 창. 시작 관측은 실제 1프레임 + proprio다.
  - 행동은 기록한 a_t = (A_t − agent_t)/100을 DINO-WM 정규화(평균·표준편차 고정값) 후 5 step씩 묶어 넣는다.
- 판정
  - a_std(앙상블)로 한다.
  - 같은 창의 실제 최종 프레임 판정으로 지각 바닥과 상상 몫을 나눈다.
- 정책 수준
  - s_π = P(r_obj < 1), n_π = P(1 ≤ r_obj < 2), ŝ_π = 상상 판정 성공률(창 하나가 episode 하나)

### 9.2 결정이 필요한 것

1. **DP(표준 과제)의 목표·판정기·정책 집합 결합**
   - 표준 PushT에는 agent 목표가 없다. 그래서 DP episode에는 원 정의(agent 포함)를 쓸 수 없고 r_obj만 정의된다. 판정기 (b)도 정의되지 않는다(목표 프레임의 agent 위치가 임의).
   - 제안
     - DP의 E2는 r_obj와 판정기 a_std(+ E3의 VLM)로 한다.
     - 원 정의와 (b)는 dset 목표 집합(E1 반사실 곡선, R2-12 교란 정책)에서만 쓴다.
   - E2의 정책 법칙(H2a)
     - 설계는 M1 정책 32개(DP 24 + 교란 8)를 셈에 넣었다. 하지만 두 집합의 목표 규약과 판정기가 다르다.
     - 제안: DP 24개를 주 분석으로 하고, 교란 8개는 통제 대비로 따로 보고한다.
     - 검정력(참 ρ = 0.6, α = 0.05, Fisher z): 32개 약 0.95, 24개 약 0.89
2. **판별기 (a) 앙상블**: K = 5 seed 확률 평균을 (a)의 정의로 고정하는 것을 제안한다(8.3절, 2.2절 근거).
3. **M3 n_π 구간**: 설계 구간 [1, 2)로 재면 π5·π6 대비가 사라진다. 선택지는 셋이다.
   - (가) M3의 n_π는 R2-9 보조 구간 [1, 1.2)로 사전등록한다.
   - (나) 설계 구간을 쓰고 대비는 곡선으로만 본다.
   - (다) 설계 구간용 far-failer를 추가한다. 정책 정의가 바뀌므로 승인이 필요하다.
   - M3 학습 실패가 r ∈ [1, 2)뿐이라는 점도 함께 적는다.
4. **dset 목표 평가 분할의 크기**: val 분할은 궤적 21개뿐이다. 반사실 3,600개가 21개 출처에 몰리므로 cluster bootstrap 구간이 넓다(R2-12: near 0.383 [0.326, 0.431]).
   - 보조 집합으로 train 분할(판별기 궤적 제외, 월드모델 학습 데이터)을 더 둘지 정해야 한다. R2-12 trainsplit에서 기억 효과는 없었다.
5. **DP 단계 확정**: epoch 20, 25, 30, 40, 50, 80, 220, 1000으로 확정할지 정해야 한다. 나머지 스냅샷은 지시대로 지웠으므로, 바꾸려면 재학습이 필요하다(seed당 약 2시간).

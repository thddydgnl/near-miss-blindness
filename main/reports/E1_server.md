   - J: 판별기 학습 2,000개
   - C: 보정 1,000개
   - T: trainsplit 보조 평가 3,000개
   - val 21개는 주 평가에만 쓴다.
2. **severity 보정**(C에서, 시뮬레이터만)
   - severity grid 21점에서 r·r_obj를 쟀다. 이분 탐색의 상한 S_MAX는 중앙값이 6.5에 닿는 가장 작은 severity로 정했다(상한 200 px).
   - 이분 탐색 정밀도도 점검했다.

   - 판별기 학습 집합용 교란 크기(50% 성공 크기)도 C에서 정했다(R2-12 calib12 방식).
3. **판별기 학습 집합**(`e1_judgeset.py`, J에서)
   - R2-12 clfset 방식을 H ∈ {3, 5, 7, 10}으로 넓혔다. H마다 500 episode × (전문가 + 교란 7개)로 16,000 궤적이다.
   - episode의 20%(413개)를 held-out으로 뺐다.
   - 구간 비율: 원 정의 0.533 / 0.171 / 0.093 / 0.204, r_obj 0.733 / 0.122 / 0.055 / 0.090
4. **판별기**(`e1_judges.py`): a_full, a_obj와 상한 판별기 ai_full, ai_obj(상상 특징, H 넷 합침)를 각각 seed 0~4로 5개씩 학습했다. 결과는 2장에 있다.
5. **a_std**(`e1_astd.py`, E2의 DP용, 지금 고정): DP checkpoint 24개 × 25 episode(seed 300000~300599)에서 프레임 11,289장을 얻어 5-seed 앙상블로 학습했다.
6. **곡선 집합**(`e1_m1_eval.py`)
   - 칸 = (분할, H, 정의). 칸마다 표적 3,600개다(r*: [0.8, 3] 층화 균등 3,000 + [0.2, 0.8) 300 + [3, 6] 300; offset·iid 반씩).
   - episode마다 표적 6개와 전문가 행동열 하나를 둔다. 도달하지 못한 표적은 새 episode로 넘긴다(최대 30회).
   - 실제 최종 프레임과 상상 최종 프레임(1프레임 시작, open-loop)에 모든 판별기를 적용했다.
   - val 8칸과 trainsplit 8칸을 돌렸다.
7. **분석**(`e1_m1_analyze.py`, CPU 환경 `b-ana`)
   - 칸마다 구간 확률, log r 로지스틱(전체 → r50·r10, 실패만 → 기울기)을 구했다.
   - 시작 상태 무작위 절편 로지스틱 GLMM(statsmodels 변분 Bayes)을 맞췄다.
   - AUROC(실제 / 상상 / 상한)와 출처 궤적 cluster bootstrap 1,000회를 계산했다.

- **두 grid를 합친 민감도**(정의 d의 곡선에 r grid와 r_obj grid의 궤적을 모두 사용): val H5 r에서 P(상상 성공 \| near) 0.146, AUROC 성공 대 near 0.953 → 0.840이다. 판정 칸 값과 거의 같다.

  - 성공 대 near AUROC는 0.953에서 0.900 / 0.853 / 0.767 / 0.673으로 떨어진다.

## 6. 편차와 결정이 필요한 것

### 6.1 편차·사고(모두 기록, 결과에 영향 없음)

1. **seed 범위 오류**
   - 원인: `e1_m1_eval.py`의 episode별 패턴 seed가 칸에 따라 2^32를 넘었다.
   - 영향: trainsplit H5·r, H3·r 두 칸이 시작하자마자 실패했다(기록 0줄).
   - 처리: seed를 2^32 − 1로 나눈 나머지로 고친 뒤 두 칸을 다시 돌렸다. 넘지 않던 칸의 seed 값은 그대로라 다른 칸에는 영향이 없다.
2. **CPU 과점(약 3분)**
   - M3 분석의 numpy BLAS가 42코어를 썼다(load 96). 즉시 멈추고 스레드 2개로 다시 돌렸다.
   - 이후 모든 B 작업에 스레드 상한(4)을 둔다.
   - GPU 0은 쓰지 않았다(가드 유지, 모든 B 프로세스 GPU 1 확인).
3. **GPU 메모리**: A와 함께 쓰는 GPU 1이 22.5GB/24.5GB까지 찼다(21:22Z, A 7.4GB + B 작업 둘). 그 뒤 B 작업은 `expandable_segments`를 쓰고, 동시에 2개 이하로만 돌렸다. 메모리 부족으로 실패한 작업은 없다.
4. a_full의 held-out 정확도는 전체 0.9585로 규칙을 통과한다. H7 부분집합만 보면 0.941이다(2장).
5. 판별기 (b)는 DESIGN_main의 고정 문턱을 썼다. 이 집합에서 다시 구한 값(0.2022, 0.3412)은 참고로만 적는다.
6. M3 n_π: 조정자 알림대로 DESIGN_main v2 §5(사용자 승인)에 따라 정책 법칙의 주 구간은 [1, 1.2)이고 [1, 2)는 함께 보고한다. E1은 정책 수준 n_π를 계산하지 않는다. 구간별 상상 성공 확률은 두 구간 모두 4장에 적었다.

### 6.2 결정이 필요한 것

1. **H1b에서 M3를 셀지**(5장 (가)·(나))
2. **물체 자세 정의의 near-miss 특이성**
   - r_obj에서는 ΔAUROC(성공 대 far)가 모든 H에서 0.02를 넘는다(0.058~0.129). 원 정의는 H ≤ 5에서 0.02 이내다.
   - 논문 서술은 "원 정의(평가기)에서 near-miss 특이적 손실, 물체 자세 정의에서는 far도 함께 흐려짐"으로 나눠 적는 것을 제안한다.
3. **원 정의의 ΔAUROC(성공 대 far)는 H7에서 0.021 [0.004, 0.041], H10에서 0.048 [0.022, 0.077]이다.**
   - near-miss 특이성(≤ 0.02)은 H5까지만 지켜진다. H7은 0.001 차이로 넘는다.
   - 판정 칸(H5)에는 영향이 없다. 다만 "특이적"이라는 서술의 horizon 범위는 정해야 한다.
